# Судебные акты в JSON: формат для других проектов

Судебный парсер собирает решения судов РК по спорам с участием ОСИ из Банка судебных актов portal-sot.kz,
разбирает их и отдаёт одним файлом `court_acts.json`. Файл можно подключить к боту (AI-юрист, помощник
председателя ОСИ): искать похожие дела, приводить примеры решений, считать, как часто суд встаёт на сторону ОСИ.

Сейчас это файл (выгрузка), а не сервис: его забирают и кладут к себе. Если понадобится запрос «на лету»
(«дай решения по теме X в городе Y»), следующим шагом будет API на сервере компании.

## Как получить

```
python -m sud_parser.practice.registry --out data/registry --json data/registry/court_acts.json <папки с решениями>
```

Одна команда строит и реестр, и JSON, поэтому данные в них совпадают.

## Устройство файла

```json
{
  "format_version": "1.0",
  "generated_at": "2026-11-23T15:26:00",
  "source": "Банк судебных актов portal-sot.kz, …",
  "personal_data": "ФИО физлиц заменены инициалами; …",
  "count": 204,
  "decisions": [ { …одно решение… } ]
}
```

## Поля решения

| Поле | Тип | Что это |
|---|---|---|
| `id`, `case_number` | строка | Номер дела, например `7527-25-00-2/12034`. Уникален |
| `court` | строка | Суд |
| `region` | строка | Город или область |
| `year` | строка | Год дела |
| `decision_date` | строка или null | Дата решения, `ГГГГ-ММ-ДД` |
| `instance`, `proceeding` | строка | «Первая», «Гражданское» |
| `language` | строка | `ru` или `kk` (казахский) |
| `category_id`, `category` | строка или null | Категория из списка 40 категорий реестра. null — категория не из списка |
| `topic` | строка или null | Тема спора по требованиям: «Взыскание задолженности по взносам…», «Возмещение ущерба…» и т. д. |
| `plaintiffs`, `defendants` | список | Стороны: `{"name": "…", "type": "ОСИ"}`. Физлица — «физлицо И. О. Ф.» |
| `third_parties` | список строк | Третьи лица |
| `special_proceeding` | да/нет | Особое производство: есть заявитель, нет ответчика |
| `claim` | строка или null | Требования истца |
| `claim_amount` | число или null | Сумма иска, тенге. null — в тексте её нет или иск неденежный |
| `verdict` | строка | «Удовлетворено полностью», «Удовлетворено частично», «Отказано», … |
| `counterclaim_verdict` | строка или null | Исход встречного иска |
| `osi_role` | строка | Роль ОСИ: «истец», «ответчик», «нет» |
| `osi_result` | строка или null | Чем дело кончилось для ОСИ: «выиграло», «частично», «проиграло» |
| `awarded_total` | число | Сколько всего взыскано, тенге |
| `awarded_to_osi`, `awarded_from_osi`, `awarded_other` | объект | Взыскано в пользу ОСИ / с ОСИ / между другими: `principal` (долг), `penalty` (неустойка), `state_fee` (госпошлина), `lawyer` (представитель), `other_costs`, `total` |
| `operative_part` | строка или null | Резолютивная часть («РЕШИЛ: …») |
| `laws` | список | Нормы права: `{"law": "Закон «О жилищных отношениях»", "article": "50"}` |
| `procedural_laws` | список | То же для ГПК и других процессуальных норм |
| `source_url` | строка или null | Ссылка на файл решения на Google Диске |
| `file` | строка | Путь к файлу: `decisions/<город>/<год>/<номер>.docx` |
| `needs_check` | строка или null | Где программа не уверена: «проверить: …». Такие поля стоит проверять глазами |
| `text` | строка | Полный текст решения без персональных данных |

## Пример чтения (Python)

```python
import json

acts = json.load(open("court_acts.json", encoding="utf-8"))["decisions"]
debts = [a for a in acts if a["osi_role"] == "истец" and a["topic"] and "задолженност" in a["topic"]]
won = sum(a["osi_result"] == "выиграло" for a in debts)
print(f"ОСИ взыскивало долг в {len(debts)} делах, выиграло полностью в {won}")
```

## Персональные данные

В `text` и других полях скрыты:
- ФИО физлиц, в том числе свидетелей и представителей (остаются инициалы);
- ИИН/БИН, номера счетов, телефоны, почта;
- номера квартир, даты рождения, номера удостоверений.

Названия ОСИ, компаний и госорганов, улицы, суммы, даты и номера дел остаются.

Обезличивание сделано правилами, а не вручную. По 204 решениям: ни одного ИИН, телефона или ФИО стороны
в выдаче не осталось. Но имя, написанное необычно, правило может пропустить. Поэтому:
- не публикуйте тексты в открытом доступе;
- если увидите незакрытое ФИО, сообщите, и правило будет исправлено.

Иногда правила скрывают лишнее: например, улицу имени человека («А. Қ.» вместо «Абай Құнанбайұлы»).

## Ограничения

- Сейчас в файле 204 решения 2024–2025 годов, в основном жилищные споры. Сбор 2021–2026 по 40 категориям
  идёт постепенно.
- Поля, отмеченные в `needs_check`, программа могла определить неточно.
