# Судебный парсер

Две части:
1. **Анализ судебной практики** (основная задача): папка с решениями судов → таблица
   (исход, суммы, статьи законов) → статистика: в каких спорах и как часто выигрывает ОСИ.
   Результаты и проверка точности — в [PRACTICE.md](PRACTICE.md).
2. **Мониторинг дел должников** (первая версия): поиск по открытому графику заседаний portal-sot.kz.

## Анализ судебной практики

**Окно в браузере** (для тех, кто не работает с командной строкой): двойной щелчок по `interface.bat`
или

```bash
python -m streamlit run sud_parser/practice/app.py
```

Откроется страница `http://localhost:8501`: перетащите файлы решений или укажите папку, нажмите «Разобрать».
Видны сводка, таблица решений с фильтрами, подробности по одному делу, нормы права, решения «проверить вручную»;
кнопка «Скачать отчёт Excel». Всё работает на этом компьютере, файлы никуда не отправляются.

**Командная строка:**

```bash
python -m sud_parser.practice --dir "C:\Users\Admin\Documents\sud-decisions"
```

- **Вход:** папка с решениями `.docx`, `.rtf` или `.txt` (файл `.doc` тоже читается, если внутри это `.docx`
  или `.rtf`; старый двоичный `.doc` нужно пересохранить в Word как `.docx`), на русском или казахском
  языке. Решения скачиваются
  из «Банка судебных актов» portal-sot.kz после входа по ЭЦП.
- **Выход:** `reports/practice_<дата>.xlsx`, листы:
  - «Сводка»: исходы по сторонам спора, предмету спора, судам, порядку рассмотрения; суммы; частые статьи;
  - «Решения»: одна строка на дело;
  - «Нормы права»: какие статьи применялись и чем закончились эти дела;
  - «Исключено»: не решения, дубли и непрочитанные файлы;
  - «Нераспознанные ссылки»: ссылки на статьи, закон которых программа не определила.

| Файл | За что отвечает |
|---|---|
| `sud_parser/practice/reader.py` | чтение .docx/.txt, включая таблицы в документе |
| `sud_parser/practice/extract.py` | разбор одного решения: стороны, исход, суммы, статьи |
| `sud_parser/practice/kz.py` | казахские слова и шаблоны: заголовки, исход, суммы, даты, ссылки на законы |
| `sud_parser/practice/analyze.py` | отбор решений (без дублей и определений) и статистика |
| `sud_parser/practice/report.py` | Excel-отчёт |
| `sud_parser/practice/app.py` | окно в браузере (streamlit) |

Принцип: то, что программа не может определить уверенно, остаётся пустым и попадает в «Предупреждения».
Программа ничего не угадывает.

## Мониторинг дел должников

Находит судебные дела по списку должников ОСИ и показывает, на какой стадии каждое дело.
При повторном запуске сообщает только **новое**: новые дела и сменившиеся статусы.

> Статус: работает с настоящим источником — открытым графиком заседаний **portal-sot.kz**
> (Единый портал судебных органов РК), и с тестовым источником `mock`.
> Какие источники проверены и почему выбран этот — в [SOURCES.md](SOURCES.md).
> Допущения и вопросы по задаче — в [TZ.md](TZ.md).

## Как это работает

```
input/debtors.csv ──► проверка входа ──► поиск в источнике ──► SQLite ──► Excel-отчёт
  (ИИН, ФИО, ...)     (ИИН, дубли)      (mock / portal-sot.kz)  (без дублей,   (сводка, изменения,
                                                                 история)       все дела, ошибки)
```

| Файл | За что отвечает |
|---|---|
| `sud_parser/models.py` | структуры данных: `Debtor` (вход), `CourtCase` (выход) |
| `sud_parser/input_reader.py` | чтение CSV/XLSX, проверка ИИН по контрольной цифре, удаление дублей |
| `sud_parser/sources/` | источники данных; каждый сайт — отдельный класс |
| `sud_parser/http_client.py` | паузы между запросами и повторы при сбоях |
| `sud_parser/storage.py` | SQLite: дела, история статусов, журнал запусков |
| `sud_parser/pipeline.py` | основной цикл; ошибка по одному должнику не останавливает прогон |
| `sud_parser/export.py` | Excel-отчёт |

## Запуск

Нужен Python 3.10+.

```bash
python -m venv .venv
.venv\Scripts\activate          # Windows; на Linux/macOS: source .venv/bin/activate
pip install -r requirements.txt
python -m sud_parser --input input/debtors_example.csv --source mock
```

Результат:
- `reports/report_<дата>.xlsx` — отчёт;
- `data/cases.db` — база;
- `logs/run_<дата>.log` — журнал (ИИН в нём замаскированы).

Имитация мониторинга (как будто прошли сутки и часть дел продвинулась):

```bash
python -m sud_parser --input input/debtors_example.csv --source mock --mock-day 1
```

Поиск по настоящему графику заседаний (нужен интернет; в файле должны быть ФИО):

```bash
python -m sud_parser --list-courts Астан
python -m sud_parser --input input/debtors.csv --source portal-sot.kz --courts 197142 --days-back 7 --days-ahead 7
```

- `--list-courts` показывает коды судов по части названия;
- `--courts` — коды судов через запятую, `--days-back` / `--days-ahead` — период;
- число запросов к порталу = суды × рабочие дни, между запросами пауза 2 секунды.

Ограничения источника (подробно — в [SOURCES.md](SOURCES.md) и [FINDINGS.md](FINDINGS.md)):
- портал отдаёт не больше 50 дел на суд и день, поэтому график крупного суда неполный и «не найдено» не значит «заседания нет»;
- в графике только дела с назначенным заседанием; судебные приказы без заседания туда не попадают;
- в графике нет ИИН, поиск идёт по полному ФИО ответчика, поэтому каждое совпадение помечено
  «ФИО (проверить)» — возможны полные тёзки;
- на дальние даты график бывает пустым (похоже, он публикуется на ближайшие дни), поэтому парсер стоит запускать регулярно.

Тесты (к сайту не обращаются, ответы портала подменены):

```bash
pytest
```

## Входной файл

CSV (разделитель `;` или `,`) или XLSX с колонками:
`iin`, `full_name`, `osi_bin`, `apartment`, `debt_kzt`. Нужен хотя бы ИИН или ФИО.
Строки с неверным ИИН и дубли не обрабатываются и попадают в журнал.

## Принципы

- **Бережно к сайту суда:** не чаще 1 запроса в 2 секунды, повторы с растущей паузой.
- **Только открытые данные:** капчи и защиту от ботов не обходим.
- **Персональные данные:** `data/`, `reports/`, `logs/` и реальные входные файлы исключены из git.
